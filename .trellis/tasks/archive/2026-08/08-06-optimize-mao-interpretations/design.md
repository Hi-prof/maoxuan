# 毛选卡片解读与启示优化设计

## Scope And Boundary

本任务只审阅 `literature.series: 毛泽东选集` 的 220 张正式卡片。内容结构、schema、Android 消费端和内容工具均不变；改动边界限定为未达标卡片的 `interpretation.explanation`、`interpretation.inspiration` 和对应 `revision`。

## Editorial Decision

采用“保留优质、重写薄弱内容”的选择性方案。逐条审阅时，符合以下全部条件的内容保持原样：

1. 解读直接说明了原句的现代含义，而非复述或截取原句。
2. 解读使用了该篇文章、写作时间、历史处境或现实问题中的具体信息。
3. 解读没有虚构作者心理、现场细节、人物对话或未经来源支持的因果。
4. 启示自然、克制、贴近日常，不是口号、训诫或主题词替换模板。
5. 内容没有把特定战争、阶级或政治判断直接当成普遍处世规则。

任一条件不满足，即同时重写该卡片的解读与启示，使两部分形成一致的阅读体验。

## Content Shape

### 解读

解读按三层组织，但不使用可见的小标题或固定句式：

1. 先用现代、自然的中文翻译原句，回答“这句话具体在说什么”。
2. 结合篇名、时间、上下文或作者当时正在处理的问题，解释这句话为何在当时出现。
3. 只有在容易误读时才补充适用边界，避免每张卡都用同一句“不能脱离历史”。

目标长度约 120 至 260 字，schema 硬上限仍为 420 个 Unicode code point。

### 启示

启示从原句中提炼一个可感知的日常观察、选择或小动作。口吻像平等交流，不使用“我们必须”“这告诉我们”“只有……才能……”等训诫结构，不要求每张卡都给行动清单。

目标长度约 45 至 100 字，schema 硬上限仍为 220 个 Unicode code point。

## Evidence And Accuracy

写作优先依据卡片已有的 `quote`、`literature`、`historicalEvent`、`background`、`story` 和 `sources`。当这些字段不足以支持具体背景判断时，回看卡片记录的原文来源；无法可靠确认的信息不写。允许描述“作者正在回应的问题”或“文章所处的局势”，但不把推测写成作者的内心状态。

## Revision Contract

- 卡片 UUID、引文、文学信息、主题、背景、故事、图片和来源保持不变。
- 实际修改解释内容的卡片，`revision` 在当前值上递增 1。
- 保持原文的卡片，`revision` 不变。
- 不修改正式卡片总数、项目版本或发布资产。

## Review And Rollback

先用结构化 YAML 审计记录修改集合，再检查模板残留、长度、NFC 和 revision 差异。自动校验之外，对修改内容按文件编号分批抽查开头、结尾和高风险战争语境卡片。若某条背景无法可靠确认，退回只解释原句与篇章问题的克制写法，不用猜测补足。

回滚以单张 YAML 为单位：内容编辑互不依赖，任何事实存疑条目都可以恢复其原解释和 revision，而不影响其他卡片。
