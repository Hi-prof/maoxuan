# 卡片与列表视觉优化

## Goal

提升阅读主卡片、搜索结果以及收藏/点赞列表的视觉品质，让内容层级更清楚、素材更有辨识度，并保持《毛选》摘读产品应有的克制、庄重和阅读感。

## Confirmed Facts

- 阅读主卡片使用同一张内容图片全幅铺底，透明度为 `17%`。
- 搜索结果与收藏/点赞共用 `CardSummaryList`，左侧显示 `76 x 102 dp` 裁切缩略图，整体透明度为 `48%`。
- 当前 8 张内容图片是低对比、浅灰红的抽象线稿；小尺寸裁切后主体识别度低，进一步降低透明度后容易显得灰、糊、像占位图。
- 当前内容已覆盖 4 个系列、30 多种卷次/作者和约 600 张卡片，但所有卡片仍循环复用同一组 8 张主题图片。
- 图片元数据已经支持 `sourceUrl`、`creator`、`license`、`licenseEvidence`、`verifiedAt` 和 `shareAllowed`，可记录档案照片的来源与分发许可。
- 列表项是带边框的 `126 dp` 高卡片，内部又嵌套一个圆角缩略图容器，形成重复框层级。
- 搜索框、搜索结果和收藏/点赞列表目前分别使用系统组件默认形态与同一套摘要卡片，没有形成连续的“文摘检索”视觉语言。
- 项目固定使用浅色主题，核心色为墨黑、朱红、纸白和中性灰；现有规范禁止渐变、仿古纹理、嵌套装饰卡片和压过正文的背景图。

## Requirements

- 主卡片背景必须保证名言、篇名和来源始终清晰，不让图片成为阅读干扰。
- 主卡片背景使用历史档案照片，并保留可验证的来源、作者/机构、许可证明和分享权限信息。
- 历史照片与卡片的映射不得暗示错误的人物、年代、地点或事件关系。
- 历史档案照片按“内容系列 + 内容主题”建立图库，第一阶段控制在约 `20–30` 张，不要求约 600 张卡片逐张配图。
- 《毛泽东选集》摘要索引优先显示卷次；其他系列使用稳定的系列简称，作者/卷次保留在正文元数据行，避免长人名挤压索引列。
- 采用混合图片策略：阅读主卡片继续保留经过重新设计的背景图；搜索、收藏和点赞列表取消内容缩略图。
- 搜索结果与收藏/点赞列表使用统一的摘要组件和统一的信息层级。
- 列表左侧改用能表达卷次、篇目或内容类别的非图片标识，在小尺寸下仍具有明确用途。
- 采用“赤印文摘”视觉语言：列表左侧使用卷次与年份索引列及朱红竖线，正文区域使用名言、篇名和状态的清晰三级层级。
- 摘要列表取消逐项外框和嵌套容器，改为全宽列表行与轻量分隔线。
- 搜索页需要弱化输入框的厚重边界，强化“输入、记录、结果”三个状态之间的连续性。
- 搜索框使用纸白填充面，默认不显示高对比红色外框，聚焦状态仅使用克制的朱红指示。
- 收藏/点赞页需要在保留独立列表状态的前提下，降低大标题、分段控件和列表之间的视觉割裂。
- 收藏/点赞分段控件应比当前实现更紧凑，并在列表上方显示当前分段的内容数量。
- 方案需兼容 `360 x 640 dp` 最小视口、长篇名、90 个字符名言、缺失图片和已下架状态。

## Acceptance Criteria

- [x] 用户可在 2-3 套明确不同的视觉方向中完成选择，每套包含主卡片背景、列表左侧视觉、搜索页和收藏/点赞页的处理方式。
- [x] 推荐方案说明颜色、字号层级、尺寸、间距、圆角、分隔方式和图片/非图片策略。
- [x] 推荐方案不依赖渐变、仿古纸纹、嵌套卡片或全屏红色。
- [x] 推荐方案能复用一个列表摘要组件覆盖搜索结果、收藏和点赞。
- [x] 方案明确图片缺失、长文本和已下架内容的显示规则。

## Out of Scope

- 本轮不修改业务逻辑、持久化 schema、搜索算法或收藏/点赞行为；仅允许新增展示所需的不可变领域投影。
- 在视觉方向确认前不进入 Compose 实现，也不批量替换内容素材。

## Decisions

- 2026-08-05：选择混合方案。主卡片保留背景图；搜索、收藏和点赞列表移除左侧缩略图，改用非图片标识系统。
- 2026-08-05：选择“赤印文摘”视觉方向。以现代文摘式排版、卷次索引和克制的朱红强调统一阅读与列表页面。
- 2026-08-05：主卡片背景选择历史档案照片，不采用定制插画或仅重新处理现有图片。
- 2026-08-05：历史照片采用“系列 + 主题”图库，兼顾史实准确、重复率、授权核验和维护成本。
- 2026-08-05：用户批准完整设计，并授权在计划完成后直接实施。
- 2026-08-05：用户批准删除已无卡片引用的 8 组旧抽象图片素材。
