# 扩充毛选卡片内容设计

## 范围与边界

本任务同时交付一个内容契约升级和一个完整内容快照：内容包从 schema 3 升级到 schema 4，正式卡片的来源下限从两个独立域名放宽为至少一个原文或权威来源；在新契约下新增 100 张 `毛泽东选集` 正文卡片。现有卡片、稳定 UUID、revision、图片资产、Room 表结构和用户状态不变。

## 数据流

```text
content/project.yaml + content/cards/*.yaml
  -> Python schema-4 严格校验与确定性构建
  -> schema-4 ZIP / schema-1 manifest / schema-4 bootstrap.zip
  -> Android code 13 严格解析
  -> 现有 Room 事务导入
  -> 阅读、搜索与推荐使用新增卡片
```

生产端和消费端同时变更。Python 只接受 `project.yaml` 的 `schemaVersion: 4` 并只生成 schema-4 JSON 信封；Android 只接受 schema 4。远端 manifest 继续使用 schema 1，通过 `minimumAppVersionCode: 13` 在下载前拦截 code 12 及更旧版本。

## schema 4 契约

- `sources` 仍为非空列表；每项必须具有非空名称、HTTP(S) URL、`YYYY-MM-DD` 访问日期和合法证据类型。
- 至少一个来源的类型必须为 `original` 或 `authoritative`；只有 `contextual` 来源的卡片无效。
- 多来源卡片仍要求 URL 互不重复，但不再要求两个不同域名。
- 其余 schema 3 字段、严格未知字段拒绝、长度、NFC、图片、withdrawal 和确定性构建规则原样进入 schema 4。
- 数据库已经按 `(cardId, position)` 存储任意数量来源，因此不改 Room schema，也不做迁移。

## 版本与兼容性

| 组件 | 旧值 | 新值 |
| --- | --- | --- |
| Android | `1.9.0` / code 12 | `1.10.0` / code 13 |
| 内容 | `1.5.0` | `1.6.0` |
| 内容 schema | 3 | 4 |
| 正式卡片 | 600 | 700 |
| 毛泽东内容 | 150 | 250 |
| 毛选正文 | 120 | 220 |
| 最低 App code | 7 | 13 |

发布顺序必须是先发布 App `1.10.0`，再发布 `content-v1.6.0`。旧 App 可继续使用已安装内容，但不能下载 schema-4 快照。新版 App 的全新安装读取 schema-4 bootstrap；已有用户升级 App 时保留 Room 中的本地状态，再通过正常内容更新导入 schema 4。

## 100 张内容分布

新增卡片编号使用 `601` 至 `700`，UUID 全部新建且不可复用。四卷最终各 55 张：

| 卷次 | 当前 | 新增 | 完成后 |
| --- | ---: | ---: | ---: |
| 第一卷 | 32 | 23 | 55 |
| 第二卷 | 37 | 18 | 55 |
| 第三卷 | 36 | 19 | 55 |
| 第四卷 | 15 | 40 | 55 |

候选优先来自当前未覆盖或仅有一张卡片的篇目。每篇最多新增 3 张，新增后同篇总数不得超过 7 张；每张从不同连续原文和不同论点切入。所有新增卡片恰好保留一个可核对的 `original` 或 `authoritative` 来源，复用现有八张原创背景图并保持使用次数大致均衡。

## 内容质量

- 引文必须逐字出现在所列原文或权威页面中，连续、单段、NFC 且不超过 90 个 code point。
- 篇名、卷次、日期和历史事件必须与来源及通行版本一致，不使用常见误传句。
- 启示说明可迁移的方法，解读说明原文语境、核心含义和适用边界；不得把历史语句包装成无条件口号。
- 背景和故事按篇目事实编写，同篇卡片可以共享历史事实，但不得机械复制整段文字。
- 正式报告用于复核卷次、篇目、主题、图片和来源域名分布；自动校验后仍保留人工内容复核事项。

## 测试与失败处理

Python 测试覆盖 schema 4、单个强来源成功、空来源失败、仅 contextual 来源失败、非法 URL 失败和确定性输出；Android JVM 测试覆盖同一矩阵，并明确拒绝 schema 3。现有 bootstrap 解析测试更新到 `1.6.0` / 700 张，推荐分类测试同步新基数。

构建任一步失败都不提交生成的 bootstrap。内容导入沿用现有事务：解析或校验失败时不切换 Room 引用，也不改变点赞、收藏、笔记和阅读进度。回滚时恢复 schema 3 代码、`1.5.0` 内容源和旧 bootstrap，不能以降低线上内容版本号的方式发布。

## 非目标

- 不同时支持 schema 3 与 schema 4，不增加宽松解析或兼容分支。
- 不改变 UI、推荐权重、Room schema、图片资产或发布工作流结构。
- 不创建标签、不发布 GitHub Release、不推送分支。
